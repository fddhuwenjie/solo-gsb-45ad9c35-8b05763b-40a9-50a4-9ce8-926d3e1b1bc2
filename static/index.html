反事实干预沙盘

勾选多个被阻止事件（干预点）并指定观察目标，系统按拓扑顺序推演 prevented / still_active。只读，不产生 changeset 或版本。 事件触发模式：ANY=任一前因发生即触发；ALL=全部前因均发生才触发；无前因的事件默认发生。

选择目标并勾选干预点后即时推演；未提交工作图即时生效。

干预点 被阻止 依据树

可复算复盘结论包

导出一个事件的自包含结论包：该事件、全部 causes 祖先与关联 supports/refutes 证据， 连同版本元数据、按包内子图重算的有效时间窗与证据审查结果，并附 SHA-256 摘要。 上传结论包文件可只读核验：先校验摘要，再仅凭包内原始节点与连线重建 DAG 重算并逐字段比对。导出与核验均不写库、不生成版本。

尚未导出 / 核验。核验仅针对上传文件，不改变当前工作图。

根因共识盲评

绑定某个不可变版本，选取 3~20 个事件作为候选，登记唯一评审人并设置最低票数。 封榜前只公开已提交名单与数量，不泄露任何排序；封榜（校验 session_revision）后按 Schulze 法计票并公开全部选票。不改写因果图、版本或结论包。

    变更提案合并

    把未提交修改保存为绑定基线版本的提案：保存时只在对应基线上复用整图校验， 不生成版本。勾选两份同基线、未合并的提案做三方比较： 单侧修改与双方相同修改直接采纳；同字段改成不同值、删除与修改相遇列为冲突， 逐项裁决（A / B / 基线 / 丢弃）后服务端在写事务中重合并并重跑成环、时间窗等校验， 全通过才生成一个合并版本并同时标记两份提案已合并。
